## How to use them

The sheets are **not graded** and you do not hand them in. They exist because programming
is not learned by watching, but it is learned by getting stuck and getting unstuck.

- Try every question **before** the solutions appear. A wrong answer you thought about is
  worth more than a right answer you read.
- For "what is the output?" questions, write down your prediction *first*, then run the
  code. The gap between the two is exactly what you still need to learn.
- Getting stuck for ten minutes is normal and productive. Getting stuck for an hour is not
  — ask, in class or in an [issue](../../issues).
- Working in pairs is encouraged.

## Sheet structure

Every sheet follows the same shape, so the mock exam in session 12 holds no surprises:

| Part | What |
|---|---|
| **A — Concepts** | Multiple choice on definitions and rules |
| **B — What is the output?** | Short code fragments to evaluate by hand |
| **C — Reasoning** | Why does this fail? Which version is better, and why? |
| **D — Write your own** | Small programs and functions, from a specification |

Parts A–C are close to the exam's first half; part D is close to its second half.
